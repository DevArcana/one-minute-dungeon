# 저장 및 마이그레이션
## 원본 분석
omd_save_v1: totalGold, upgrades(atk/def/hp/gold/luck/firstCrit), inventory/equipped 객체, bestiary, achievements, pet, quests, killCounts, lastClass, relicsSeen, 기록/설정 등.
omd_run_v1: 전투 및 진행 중 상태. 원본은 복원 직후 enterRoom을 다시 실행하여 적을 재생성한다.

## V2
omd_save_v2 한 JSON에 영구 진행과 run을 함께 저장한다. run에는 phase, 지도/경로, 자원, HP, 적 체력/턴/상태, 유물 후보, log, 시드, 결과를 포함한다. 모든 명령 뒤 1회 저장한다. 결과 진입 시 한 번만 보상을 지급한다. 결과 저장 후 다시 로드해도 settle은 재지급하지 않는다. 종료 시 중복 저장하지 않아 오래된 페이지가 새 상태를 덮어쓰지 않게 한다.

## 변환
- 골드/플레이/클리어/최단시간/도감/업적/처치/선택 클래스/사운드: 유효 값 변환.
- 성장: 키별 새 최대 레벨까지 인정. 초과 레벨당 50G 보상. 새 효과 수치에 맞춰 계산.
- 장비: 원본 일반/고급 무기→문지기의 검, 상위 등급→독니 단검. 일반/고급 갑옷→서약의 갑옷, 상위→황혼의 망토. 반지→새벽의 인장. 같은 대응 장비는 하나로 합친다. 장착 슬롯 변환.
- 펫·퀘스트·미지원 장비 특수효과·기존 유물/업적 상세 등: legacy.snapshot에 원본 전체 보관. 직접 사용하지 않는 원본 키도 삭제하지 않는다.
- 구버전 진행 중 탐험은 구조가 달라 V2에서 이어하지 않는다. omd_run_v1은 그대로 남긴다.
- V2가 있으면 V1을 다시 가져오지 않아 재지급을 막는다.

## 검증과 실패
숫자 유한성/범위, 데이터 ID, 방 배열/경로, HP/자원/적 턴, phase를 검사한다. 구조가 손상된 run은 폐기하되 영구 데이터는 정규화하고 원본을 복구 키에 보관한다. 손상된 JSON은 omd_save_v2_recovery에 최초 1개 백업한다. 백업 불가 시 기존 키를 덮어쓰지 않는 임시 플레이로 전환한다. 미래 버전은 덮어쓰지 않는다. 저장소 차단/용량 초과는 화면에 표시한다.

도움말에서 현재 V2 상태를 JSON으로 내보내고 다시 가져올 수 있다. 가져오기는 최대 5MB의 완전한 V2 백업만 허용한다. 파일 선택 후 클래스·골드·완료/클리어 기록·탐험 유무를 확인하고 복원을 선택한다. JSON 오류, 다른 버전, 누락/손상 데이터는 거부하며 현재 기록을 변경하지 않는다. 키 순서가 다른 JSON과 UTF-8 BOM은 지원한다.

복원 직전 저장된 원본은 omd_save_v2_before_import에 보관한다. 이 백업 저장이 실패하면 복원하지 않는다. 현재 세이브 쓰기가 실패해도 화면의 진행 상태는 교체하지 않는다. 도움말의 “복원 전 기록 내려받기”로 이전 기록을 내보내 다시 가져올 수 있다. 복원 전 백업은 가장 최근 1개만 보관하므로 여러 기록을 보관하려면 먼저 내려받는다. 미래 버전 또는 저장소 보호 모드에서는 가져오기를 비활성화한다. 기기/출처 간 동기화도 없다. 여러 탭에서 기록을 변경하면 오래된 탭은 입력과 저장을 중단한다. “최신 기록 불러오기”로 재개하거나 “현재 탭 기록 백업”으로 화면의 진행을 따로 내보낼 수 있다. 불러오기 대기 중인 백업 미리보기도 취소한다. 파일 URL과 웹 호스팅은 별도 저장소다.

## 다중 탭 저장 제어
동일 출처의 탭들이 omd_save_v2 이름의 Web Lock을 공유한다. 초기 로드/마이그레이션/저장, 일반 행동, 난도/소리 설정, 백업 복원의 읽기·비교·변경·저장을 잠금 안에서 순서대로 수행한다. 직전 로드/성공한 저장의 원문과 현재 저장 원문이 다르면 행동 전에 차단한다. 저장 실패는 비교 기준을 갱신하지 않는다.

storage 이벤트(키 삭제와 clear 포함), 탭 포커스/재표시, 각 변경 입력에서 확인한다. 충돌 상태는 자동으로 해제하지 않고 명시적으로 최신 기록을 다시 불러오게 한다. 오래된 탐험·장비·성장·설정·복원 입력은 모두 차단하되 조회와 백업은 허용한다.

Web Locks가 없는 환경은 원문 비교와 이벤트 감지만 지원한다. 해당 환경의 정확히 동시인 쓰기에는 원자성을 보장하지 않는다. 구버전 게임이나 개발자 도구처럼 같은 잠금을 사용하지 않는 외부 쓰기도 잠금으로 제어할 수 없다. 출처/브라우저/기기 간 동기화 기능은 아니다. Web Locks 동작 근거: https://www.w3.org/TR/web-locks/
