# 리메이크 계획과 원작 분석
원본은 정적 HTML/CSS/JS 5개 파일. PROJECT_HANDOFF.md, AGENTS.md, 테스트 설정은 없다. main에 원본 보존. README와 실제 코드를 비교하며 실제 코드를 기준으로 설계한다.

game.js는 데이터·DOM·저장·오디오·전투를 전역 상태로 연결한다. 순차 10방, 4/7방 유물, 5방 미니보스, 10방 보스. 클래스는 수치 패시브만 제공한다. 공격 뒤 타이머로 적 턴을 실행하며 보스는 일반 확률 능력을 공유한다. omd_save_v1 / omd_run_v1에 저장한다. 복원 시 enterRoom이 적을 다시 만들고 applyEquipToRun은 비어 있다. 결과 보상은 여러 번 저장된다. 별도 데스크톱 CSS가 같은 DOM을 재배치한다. Web Audio 합성음은 외부 의존성이 없어 유지할 가치가 있다.

| 기능 | 결정 | 이유 |
|---|---|---|
| 탐험→전투→보상→성장 | KEEP | 핵심 정체성 |
| 정적 호스팅/localStorage/Web Audio | KEEP | 서버 불필요 |
| 클래스/전투/상태이상/보스 | REWORK | 자원·독·화상·방어·예고로 판단 강화 |
| 던전 | REWORK | 9단계 분기, 위험/보상 공개 |
| 장비/유물/시너지 | REWORK | 영구 장비와 판 한정 유물 구분 |
| 영구 성장/도감/기록 | REWORK | 핵심 루프에 연결 |
| 자동전투/콤보 연타 | DELETE | 행동 선택 보존 |
| 가챠/채굴/방치/웰컴백 | DELETE | 던전 외 반복 행동 축소 |
| 펫/진화/퀘스트/헌터/보스러시/스토리 | DELETE (이번 범위) | 데이터 보관, 핵심 이후 재검토 |
| 기록 삭제 하드코어 | DELETE | 진행 보호 |
| 적 의도/안전한 이어하기/선택 난도 | NEW | 전략성과 복원 신뢰성 |
| 생성 아트/반응형 UI/키보드 | NEW | 가독성과 접근성 |

순서: 순수 시스템 → 저장 검증 → 한 판 플레이 → 생성 아트 → UI → 시뮬레이션/브라우저 검증. 3~5분은 선택 읽기 포함 목표, 실측으로 추가 보정.
